- N2 (test-engineer). tests/adversarial/Phase10Http.scala around line 575: the `BodyBaseline` calibration fake runs `while in.read() >= 0 do ()` after answering 401, though its docstrings (:548-551, :834-836) and report 12 say it never reads. The baseline grew from 131072 bytes at answer time to 2555904 after the grace period, while the real service stayed flat (720896 at both points): a byte-at-a-time reader, not buffering. The after-grace limit (baseline plus 2 MiB) therefore depends on loop speed; on a faster host it can climb to the 16 MiB declared/4 cap, bringing the M10 weakness back for any server that answers and then reads up to about 4 MiB. Only the after-grace check can catch that case, and no negative control covers it. Still holds: a server that reads 4 MiB before answering is caught by the at-answer check by about 2.8 MiB (a genuine control, asserts at least 4 MiB written and that the failure message names the limit). Fix: make the calibration fake hold the socket open without reading (like `holdUnread`); add an "answer, then read 4 MiB" negative control; re-measure margins.
