## 1. arXiv key
`SideRecord.workArxiv: Option[String] = None` (trailing, defaulted, absent from JSON when empty). `Identifiers.workArxiv(arxivId, doi)` reads `WorkRecord.arxivId` first then the arXiv-prefixed DOI form and reduces to the bare id without version suffix (`2101.00001v2`, `arXiv:2101.00001v3`, `https://arxiv.org/abs/...`, `.../pdf/...v1.pdf`, `10.48550/arXiv.2101.00001` in any case with doi:/https://doi.org/ prefixes, legacy ids such as `cs/0112017`; anything else None). `AuthorSlots.sharedWorkKey`: DOI key if both sides share a normalized work DOI; else the arXiv key if both share an arXiv id; the arXiv key is skipped when both sides carry a work DOI and the two differ. Same conditions as DOI (both positions known and different, equal-length aligned lists, same person at every index). New codes `rule.same-arxiv-distinct-position`, `rejected.same-arxiv-distinct-position` (deterministic-bibliographic, REJECTED). A preprint and a published version with a different DOI and no shared arXiv id are not conflated; if the published version carries the same arXiv id and the lists align the rule fires (intended, tested).
