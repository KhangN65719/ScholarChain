## Built
- `Pass3Subset` tool: complement of pass2-subset.txt (153 pairs) in a SHA-256 shuffle with its own salt `scholarchain-phase5-pass3/1` (refuses the pass-2 salt), no strata key and no suggestions; prints counts, "disjoint", "77 + 153 = 230 of 230 pairs" and the output SHA-256.
- `LabelServer --relabel-pass 3` with `--only` and `--carry-from gold-v2.jsonl`: pass-3 rows `pass:3`, human, null suggestion fields, `changed_from_suggestion:false`, `pass1_label` copied from pass 1 (never shown); pass-2 rows carried value for value plus `carried_from` / `carried_from_sha256` (gold-v2). Replaced pass-1 rows' lines and suggestion fields are dropped. Guards: --gold may not be the carry file or a sibling named in `carried_from` (gold.jsonl), a gold file with pass-1 rows or no `pass` is refused, repeated subset ids refused. Page: "Pair k of 153 (subset)", "Blind pass 3 over a subset", no suggestion keys, stratum, pass-1 label or matcher output; a test scans labeling sources for error-analysis words, decisions.jsonl and the strata key. Old pass-2 invocation unchanged (BlindPassSuite untouched and passing).
- `GoldValidator --mode v3 --pass1 --pass2file --subset [--pass2-subset --strata-key --reviewer]`: 230 entries, ids both ways, GoldLabel validity, `pass` in {2,3}, pass-3 rows exactly the subset and blind with pass1_label equal to gold.jsonl, pass-2 rows equal to gold-v2 lines, subsets disjoint and complete, no suggestion field anywhere; review time printed first for pass 1 (all of gold.jsonl), pass 2 (gold-v2 pass-2 rows) and pass 3 (span, median gap, gaps under 2 s); label counts by pass; blind-review line; descriptive pass 1 vs pass 3 agreement (agreement, Cohen's kappa over same/different with unsure counted separately, changes by direction, disagreements by pair_id, strata only with the key); reads no matcher output; never changes pass/fail. `--suggestions` and `--expect-changed` refused.
- `EvaluationRun` accepts v3 (overall, by pass, by stratum); `--compare-with <evaluation-report.json>` appends a text block: pooled counts/precision/recall/F1, the pass-3 pairs whose label changed with matcher outcome, path, score and reasons, and counts of changes among pairs the earlier report listed as errors versus others (to show whether changes cluster on matcher-flagged pairs); WARNING on pairs-digest or policy-version mismatch. The v2 label of a pass-3 pair is its stored `pass1_label` (gold-v2 carried pass-1 labels unchanged). Descriptive only.
