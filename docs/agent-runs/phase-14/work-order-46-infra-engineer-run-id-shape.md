# Work order 46: infra-engineer, the pinned run id must be a valid stable run identifier, refused before any spend

Owner: infra-engineer (scripts/**, scripts/emr/**). Edits in those paths only. No AWS, no commit, no ~/.aws. The guard blocks agent grep, find, bash -n and shellcheck; the human runs those.

Evidence (human `!` runs, S run 2, 2026-11-14; decisions-d29.md, read it first): the Hadoop stage failed in `DblpExtractionJob$ExtractMapper.rejectRecord` with `IllegalArgumentException: requirement failed: Malformed run identifier` (`StableIds.requireKind` from `Provenance`, built by `RunContext.provenance`). Read from the sources (orchestrator, read only): `modules/core/.../StableIds.scala` `newRun()` is `run:v1:<UUID>`, `isKind("run", ...)` requires exactly `run`, `v1` and a payload that matches `uuidPattern`; `RunContext.runSlug` is `runId.replace(':', '-')` and the output path is `<root>/run=<slug>/snapshot=<digest>`. The scripts pinned `-Dscholarchain.run.id=s-20261114-2`, which is not that shape; `run-bounded-pipeline.sh` and `run-s-pipeline.sh` accepted any path-safe id of up to 64 characters, so nothing refused it before an eight-minute cluster launch.

Design (human-approved direction, orchestrator's proposal): the execution input's `run_id` is the path-safe slug `run-v1-<uuid>` (lower-case canonical UUID, 36 characters, so the slug is 43 characters). The scripts turn the slug into `run:v1:<uuid>` for the `-Dscholarchain.run.id` option. The slug stays the S3 prefix component, the on-node work directory name, and the loader's argument.
