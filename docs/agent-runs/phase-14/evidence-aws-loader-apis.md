## S3 Vectors metadata filtering (https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-metadata-filtering.html)
- Operators: `$eq`, `$ne`, `$gt`, `$gte`, `$lt`, `$lte`, `$startsWith` (ENHANCED only), `$in`, `$nin`, `$exists`, `$and`, `$or`. A bare `{"genre": "x"}` means `$eq`. Multiple operators on one field are allowed (`{"price": {"$gte": 10, "$lte": 50}}`).
- `$eq` against an array metadata value is true if the input matches ANY element (so "researcher OR evidenceNodeIds list-contains" is expressible as `$or` of two `$eq`; this resolves report 16's UNVERIFIED list-contains point).
- Metadata types: string, number, boolean, list. Filterable by default; non-filterable keys must be declared at index creation and cannot be filtered; non-filterable keys come back with `return-metadata`. Oversized filterable metadata makes PutVectors return 400.
- Index modes: `ENHANCED` (pre-filtering, high recall; vector buckets created on or after 2026-09-30 create ENHANCED indexes) and `CLASSIC` (filter evaluated during the search; a filtered query can return fewer than top K when few vectors match; buckets created before that date). Our vector bucket was created by the 2026-11-14 foundation apply, so its indexes are expected to be ENHANCED (not confirmed: the Terraform index resource and any explicit mode were not read). Up to 100 filter constraints per query on ENHANCED.
- Other pages found, not read: https://docs.aws.amazon.com/AmazonS3/latest/userguide/s3-vectors-query.html (QueryVectors, pagination with nextToken), s3-vectors-limitations.html (batch and metadata limits).

## Neptune openCypher bulk load format (https://docs.aws.amazon.com/neptune/latest/userguide/bulk-load-tutorial-format-opencypher.html)
- Nodes and relationships are separate CSV files (RFC 4180, UTF-8); one load job loads many files; ALL files to load must share one S3 path prefix given as `source`; file names and extensions are not important (so a `load-manifest.json` under that prefix would be picked up: confirms report 16's risk that NeptuneExporter's manifest under the same prefix would be loaded as data).
- Node file system columns: `:ID` (required; optional ID space `:ID(space)`; unique across files and across current and previous loads), `:LABEL` (several labels separated by `;`). Relationship file: `:START_ID`, `:END_ID` (required), `:TYPE` (single type), `:ID` (required when `userProvidedEdgeIds` is true, the default; invalid when false).
- Property columns `name:Type`; no spaces, commas, CR or LF in headers. Documented types: Bool/Boolean, Byte, Short, Int, Long, Float, Double, String, DateTime (ISO-8601 forms), plus auto-cast Char, Date, LocalDate, LocalDateTime, Duration, Point (stored as strings). NO array type (`String[]`) is documented on this page: report 16's recollection of `String[]` with `;` is not supported by this page; the exporter's headers must be checked against it.
- Not read: the loader API reference https://docs.aws.amazon.com/neptune/latest/userguide/load-api-reference-load.html (openCypher parameters: `format` opencypher, `userProvidedEdgeIds`, `parallelism`, role ARN, `s3BucketRegion`, duplicate-ID handling), https://docs.aws.amazon.com/neptune/latest/data-api/API_StartLoaderJob.html.
