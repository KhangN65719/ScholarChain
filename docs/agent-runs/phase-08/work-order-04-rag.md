## Required work
1. Deterministic rendering templates (implement storage's `SummaryRenderer`) for researcher profiles, community profiles, collaboration paths and representative-paper summaries. Pure functions of the row only: no clock, no randomness, no locale. Fixed field order and wording; a template version string per document type (e.g. `rag-template/researcher-profile/1`). They may restructure what the Spark row already contains (the `summaryText`, `evidenceMetrics`, window, IDs) but must NEVER introduce a number, metric, ID, name or claim that is not in the row: the Phase 6 rule is that summaries come from computed data. State uncertainty or missing fields explicitly rather than guessing (e.g. a null `nodeKind`, an unreachable path). An unknown summary type is refused with a clear error, not rendered generically.
2. Chunking policy for permitted abstracts or longer text: a pure, deterministic function (bounded chunk size in characters at word boundaries, a fixed small overlap, stable chunk ordinals, chunk ID derived from entity ID, source version, document type, ordinal and text hash per the README's stable-ID principle, using core `StableIds` if a suitable function exists, else report the gap as `BLOCKED-ON domain-engineer`). Phase 6 summaries are short, so the policy is exercised by tests and documented; it is not forced on the Phase 6 summaries unless they exceed the bound. Never silently truncate.
3. Embedding model versioning: a small registry in rag naming the model version string (`hash-embed-v1`), its dimension (384), the index-name suffix rule (a new model or dimension means new `-vN` index names, never an in-place change, per Phase 7 D7), and a check that fails loudly when an `Embedder`'s `modelVersion`/`dimension` do not match what the ingest config expects. Do not duplicate `HashEmbedder`.
4. Retrieval smoke tests with known expected neighbours, using `HashEmbedder`, the five index specs, `InMemoryVectorBucket` and a hand-built fixture of summaries (researchers, communities, works, paths with clearly distinct vocabulary), ingested through storage's `EmbeddingIngest` with your templates. Assert: a query built from a topic's words returns the expected researcher/community/work first; filters (documentType, window/year, community, researcher) narrow correctly; `fetchText` on a hit returns the rendered text through its S3 pointer; the same key with different text is refused. Assert the structural gate: results carry no graph metric from vector similarity (exact counts, shortest paths, components, bridge metrics are not answered from vectors; the context format below must mark them as "from graph or metric stores, not from this retrieval").
5. Compact semantic-context format for the synthesis agent: a versioned, bounded, JSON-serialisable record of retrieved items: vector key, document type, distance, window, subject ID, evidence work and node IDs, text reference, and the retrieved text snippet bounded to a documented maximum length, plus an explicit field stating deterministic metrics are not included and must come from graph or metric stores. Serialization and deserialization tests; a hard cap on item count and text bytes; refusal of oversize input rather than truncating silently.
6. `IngestMain` (`scholarchain.rag.IngestMain`): the composition point for the local real-data run. Arguments: the JSONL export directory (the human's Phase 8 export), an output directory for the local fakes' persisted artifacts, and an optional bound. It opens `JsonlExportSource`, uses `HashEmbedder`, your templates, local file-backed or in-memory fakes (use what storage provides; if the object store fake is in-memory only, write a final report file with counts, per-index vector counts, object counts and bytes, local timings, rejects and skip counts to the output directory), then runs `EmbeddingIngest` and prints a clear `PHASE8-INGEST RESULT: SUCCESS|FAILED` summary, then a few sample filtered queries with latency (labelled LOCAL) and a `fetchText` check for each. It must be re-runnable with identical results and refuse a nonexistent or incomplete export. No AWS client code. The orchestrator will give the human one paste-ready `!` command from your report, so state the exact `sbt "rag/runMain scholarchain.rag.IngestMain <args>"` form, what success looks like, and memory expectations (sbt default heap for ~42k rows and 384-dim vectors; say if it needs more).
7. Feature tests for every behavior change in `modules/rag/src/test` (munit, already available). Template determinism and the no-invented-values property (every number and ID in the output appears in the input row); every summary type; unknown type refused; chunking boundaries, overlap, determinism, no loss (concatenation reconstructs the text modulo overlap); registry mismatch; smoke tests above; context-format round trip and caps; IngestMain on a tiny fixture export (success, missing export refused, rerun identical).
