# Phase 10 decisions

Recorded by the orchestrator, 2026-11-08. "Human" decisions came from AskUserQuestion. The rest are conservative defaults taken under the standing instruction to decide and record. Any can be reversed at the gate.

| # | Decision | Basis | Why |
|---|---|---|---|
| D1 | HTTP transport is the JDK `com.sun.net.httpserver.HttpServer` (module `jdk.httpserver`, Java 21, GPLv2 with Classpath Exception). No new dependency and no ledger change. | Human, 2026-11-08, chose the recommended option over Javalin 6 and Helidon SE 4 | Zero supply-chain surface, no build or ledger churn, virtual-thread executor on Java 21. Cost is a small hand-written router. Routes stay thin. |
| D2 | JSON is uPickle 4.4.3 from the ledger. No second JSON library. | CLAUDE.md | One JSON library rule. |
| D3 | `POST /v1/query` is synchronous by default. `"mode":"async"` in the body, or `Prefer: respond-async`, returns 202 with a job reference. Jobs run on a bounded in-process executor behind a job-store port with an in-memory local fake. | Default | Matches the course fast and slow paths without queues. SQS and Step Functions are deferred to Phase 12. |
| D4 | Idempotency: optional `Idempotency-Key` on POST. Same key and same body hash replays the stored response with the same queryId. Same key and a different body is 422. The idempotency store sits behind a port with an in-memory fake. | Default | DynamoDB conditional writes are deferred to Phase 12. |
| D5 | Authentication is a static bearer token read from configuration (environment variable name only in the repo, placeholder value for local runs), compared in constant time. Two scopes: `query` (POST /v1/query) and `read` (every GET under /v1). `/healthz` and `/readyz` are unauthenticated. Missing or invalid token is 401, valid token with the wrong scope is 403. No token value appears in responses or logs. | Default | Appropriate to a local course deployment. Secrets Manager injection is deferred to Phase 12. |
| D6 | Timeouts, bounded retries and a circuit breaker wrap each downstream port call. Retries apply only to idempotent reads, at most 2. A timeout is 504, an open breaker or downstream failure is 503, both with the typed error body and a trace ID. | Course spec | Policy values come from configuration, not literals. |
| D7 | `GET /metrics` is an in-process, plain-text endpoint, enabled by a configuration flag that defaults to off. When off it returns 404. It sits behind the `read` scope. | Default | The deployment model is undecided. This keeps the course item without committing to an exporter. |
| D8 | "Independently scalable services": one `services` sbt module, with a fast read service (evidence, graph, explain, ops) and a slow service (query, jobs) each separately mountable on its own port with its own deadline policy. A local runner composes both. No separate sbt modules. | Default, conservative | CLAUDE.md fixes the module graph. A new sbt module is a build-scope change. |
| D9 | The services module depends only on core, rag and storage, and calls the Phase 9 workflow through rag ports with the deterministic offline stub and the storage local fakes. No AWS SDK, no Bedrock. | Scope note | CLAUDE.md module boundaries. |
| D10 | Container image, `dockerLocal`, ECS and ALB health wiring are not exercised. Agents do not run Docker. They are recorded as deferred to Phase 12 or 14 unless a Dockerfile already exists and build-engineer can verify it statically. | Scope note | No image pushes or deploys. |
| D11 | Build changes go only to build-engineer, and only if the service-engineer reports `BLOCKED-ON` build-engineer. None is expected. | Default | Avoids a speculative build edit. |
| D12 | The test-engineer runs in parallel with the service-engineer but runs no sbt command in the first dispatch, because two sbt commands must never run at once. A second, sequential dispatch executes and reports the tests after the service-engineer finishes. | Human instruction, "never run two sbt commands at once" | A written but unexecuted test is not evidence, so the second dispatch is required. |
| D13 | Review round 1, M1 ruling: a query constraint the Phase 9 workflow cannot apply is refused with 422 `UNSUPPORTED_CONSTRAINT`, never accepted and ignored. This covers topic, venue and institution filters, `limits.maxResults` unless the workflow can honor it, and a structured window that conflicts with a year in the question. This narrows spec.md, which listed filters as allowed fields: they stay in the schema and are validated, but are refused until the workflow supports them. Tests that treated `filtersApplied:false` as supported are changed to expect 422. This corrects a wrong expectation, it does not weaken a check. | Orchestrator, conservative, reversible at the gate | Course spec: an unsupported constraint is 422. A silent 200 that ignores a requested constraint is the worse failure. Phase 12 can enable filters when the real retrieval exists. |
| D14 | Review round 1, M2 ruling: each service gets its own call pool with a bounded queue, and the HTTP executors are bounded. A full queue returns 503 `OVERLOADED`. A slow workflow must not affect an evidence read or its breaker. | Reviewer finding, course rationale for separate services | D8 and the work order's thread-bounds item. |
| D15 | Review round 1, m3 ruling: `GET /v1/jobs/{id}/result` for a failed job returns 409 with code `JOB_FAILED`, with the job's original error code in `details`. It no longer replays the original status. Add `JOB_FAILED` to the error enum and document it. | Orchestrator, conservative | A GET that completed must not look like a retryable 504. 409 already means the result is not available. |
| D16 | Review round 1, m5 ruling: bounded multi-hop traversal in `GraphService` is accepted for Phase 10 as a read-through for the graph exploration API. The misleading "never retrieves, ranks" wording is corrected. Moving traversal into storage or rag is deferred to Phase 12 with the live Neptune templates. | Orchestrator, conservative | A relocation is a cross-module change across three owners and is out of scope for a repair round. |
| D17 | Unowned untracked files (AGENTS.md, .agents/, .codex/, datasets/slice/, docs/agent-runs/phase-06/readback-paths.py, .DS_Store files) stay out of the Phase 10 commit, as in Phase 9. | Phase 9 ratification, reviewer note | No owner in docs/agents.md. |
